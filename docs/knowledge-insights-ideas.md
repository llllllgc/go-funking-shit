# 记录回顾与个性化小纸条：产品构想

目标：帮助用户回看自己记录过的形态与时间，并给出温和、可操作的生活建议。输出应是“记录回顾”，不是健康评分、诊断或每日打卡提醒。入口适合放在历史页，首页继续保持一条轻量小纸条。

## 现在的数据能做到什么

每条记录只有实际发生时间和保存的形态。显示在列表中的 01–07 是界面序号；分析必须使用保存的原始形态编号：1–2 偏硬，3–4 成形，5 柔软小块，6–7 偏稀。既有记录不改动。

| 回顾 | 可展示的事实 | 纸条语气示例 |
| --- | --- | --- |
| 近 7 天形态分布 | 各形态被记录的次数、哪些天有记录 | “最近记录里，偏硬的形态出现得更多。可以回想饮水、饮食和活动有没有变化。” |
| 与前 7 天比较 | 两段时间内已记录形态的构成变化 | “和上一段记录相比，偏稀的记录多了一些。先观察是否持续，也留意补水。” |
| 同一天多次记录 | 该日的实际记录次数和顺序 | “这一天记了不止一次。若反复是水样便，也留意口干、尿少等情况。” |
| 时间分布 | 已记录事件常出现的时间段 | “记录多在饭后。若方便，可以继续观察自己的节奏。” |

这些文案只是示意模板，必须由真实记录填入事实部分。没有记录的日期只能写“未记录”，不能推断“没有排便”；不能由形态推断食物、疾病、体内水分或疼痛。时间分布也只是回顾，不代表哪种时段更健康。

## 建议的第一版规则

1. 默认只显示客观回顾：“近 7 天记录了多少次，哪类形态出现较多”。没有足够数据时只显示记录入口，不做趋势判断。
2. 趋势比较需要前后两段都具有多条记录、跨多个记录日。门槛是产品降噪规则，不能被表述为医学阈值；单次异常不触发“你可能有某病”。
3. 偏硬较多时，可从纤维逐步增加、足够饮水、规律活动与从容如厕中轮换一条建议；偏稀较多时，优先给出补水和需要留意的症状。两种形态交替出现时只描述现象，不强行归因。
4. 一张卡只放一条结论、一条建议，并标明“基于你已记录的内容”。点击后展开来源和适用边界，不在首页叠加多张提醒。
5. 每条建议都指向固定、经过审核的小纸条及来源；规则和文案离线运行，不上传个人记录。

## 以后若增加可选记录项

优先考虑“是否排出费力／疼痛”“是否有急迫感”“是否看到血或黑色柏油样便”等简短、可跳过的自述项。饮食、饮水、活动只能作为用户自选的观察线索，不能由同时发生推断因果。用户主动报告便血、黑色柏油样便、明显腹痛或脱水迹象时，显示明确的就医建议；系统不能仅凭形态编号推断这些信号。

上线前需要核对每条个性化建议与其医学来源，特别是就医提示。相关基础资料见 [小纸条知识库](knowledge-base.md) 中的官方来源。

## 呈现形式：先评审，再实施

交互草图见 [三种回顾方案](../tool/prototypes/insights-ui.prototype.html)。目前建议采用 A：历史页在“共 N 笔记录”下方放一行轻入口“记录回顾 · 近 7 天”，点开独立页面。首页仍只显示一条简短小纸条，不叠加数据图；日常记录按钮和按日期查找的历史列表也不改变主次。

独立页按“一个客观结论 → 记录量 → 形态分布 → 一条小纸条 → 计算方式与局限”排序。结论必须写“在已记录内容里”，小纸条只给一件可做的事；来源和适用边界按需展开。形态分布用明确数量和文字标签，颜色只辅助识别。日期空白标为“未记录”，不画作 0 次排便。

另外两种方案可在草图中比较：B 在历史列表上方展开小结，优点是少一次跳转，但会推低记录；C 把历史分成“记录 / 回顾”两个标签，更适合分析内容明显增加以后，当前会增加找记录的操作。A 是当前推荐，尚未作为最终设计决定，也未接入正式 App。

低数据量状态不显示趋势图或个性化建议：例如近 7 天只有 1 笔时，只说明“记录了 1 次，分布在 1 天”，邀请用户继续记录。该降噪门槛是界面规则，不是医学标准。第一版不要放健康分、红黄绿评级、连续打卡天数或未经核对的周环比；待有真实使用反馈再决定是否增加更长周期比较。
