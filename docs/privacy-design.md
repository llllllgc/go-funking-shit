# 应用锁与后台遮挡

## 保护边界

这是应用内访问保护，不是数据库或备份加密。设备的有效面容、指纹或锁屏凭据都可以用于系统验证；应用不读取这些凭据。已导出文件、系统备份、被破解设备，以及其他人掌握设备凭据的情况不在应用锁的保护范围内。iOS 不能据此宣称阻止前台截图。

默认关闭，仅在用户主动开启并成功验证后保存设置；关闭也需要验证。无法验证时没有绕过入口，需要恢复设备验证能力。没有在启动时主动请求生物识别权限。

## 持久化和状态

- SQLite schema v3 的 `app_settings` 保存 `app_lock` 布尔值。读取异常中止启动；写入或原生保护结果不确定时隐藏内容，先重新读取配置。
- 设置与日志独立；导出备份不携带设备锁定偏好，导入/清空日志也不改变它。
- 普通失焦、后台、隐藏都会遮挡；非验证窗口导致的失焦重新锁定。系统验证窗口短暂 inactive 不触发递归验证，真正进入后台会使旧验证结果失效。
- 验证回调需匹配当前会话代次。验证成功但恢复前台事件尚未到达时，先保持遮挡，到正确的 resumed 才显示内容。
- 锁屏在 Navigator 之上；表单、弹窗和数据预览隐藏，焦点及语义不可达。没有清除草稿或删除日志。
- 生产日志控制器在新建、修改、删除、恢复、导入与清空前检查访问策略，防止迟到的界面操作在锁定状态写入。
- 后台编码完成的导出必须重新检查当前访问代次，才能打开系统保存窗口。已经交给系统的文件操作由系统管理。

## 原生层

- iOS SceneDelegate 在失焦/后台加入不含记录的原生遮挡层。每次遮挡增加序号，只有当前前台序号对应的 Flutter 安全帧确认才能移除它。
- Android 启动默认保护窗口，待成功读取设置后按偏好应用 FLAG_SECURE；API 33+ 使用 `setRecentsScreenshotEnabled(false)`。暂停时加入原生遮挡，当前代次的安全帧确认后移除。旧 Android/OEM 行为仍需设备验收。
- `debugStatus` 仅在 iOS Debug 编译条件下用于探针，Release 不包含此入口。`tool/privacy_probe.dart` 不读取日志，仅在独立测试模拟器记录遮挡状态和序号。

## 验证分层

1. `privacy_controller_test.dart`：读取/写入失败、取消、不支持、重复调用、后台旧结果、恢复前台顺序与访问代次。
2. `privacy_flow_test.dart`：首屏隐藏、语义与焦点不可达、表单保留、真实生命周期通知、迟到的帧确认、双倍字号。
3. `bootstrap_test.dart`、`sqlite_repository_test.dart`：隐私初始化失败、迁移、偏好持久化及日志操作不改变偏好。
4. `data_flow_test.dart`：后台后完成的编码不打开保存窗口。
5. 独立 iOS 模拟器原生探针：已验证旧序号 0 在当前序号 2 下不能移除遮挡，正确序号可以移除。该结果不等于生物识别成功流程或全部截图行为已验证。

真实 Face ID/指纹/设备密码成功和锁定/拒绝/中断流程、Android 不同版本的任务预览、截图、投屏，以及外部文件提供者返回仍需正式设备验收。测试替身的“成功”不能代替这些结果。

实现依据：[local_auth 官方用法](https://pub.dev/packages/local_auth)、[Android 平台配置](https://pub.dev/packages/local_auth_android)。
