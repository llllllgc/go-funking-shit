# 删除与恢复

## 用户可见行为

- 单条删除成功后，在当前页面底部提供“恢复记录”和“关闭提示”。提示不会因停留时间而自动消失。
- 恢复写入期间显示“正在恢复记录…”，禁用重复点击和关闭按钮。恢复成功后，原记录重新进入首页、历史和统计，提示关闭。
- 恢复失败时，提示保留并提供“重试恢复”。原 ID、发生时间、更新时间、备注与不适保持不变。
- 关闭提示、切换底部页面、打开其他页面、下一次删除替换提示或退出应用，会结束这次恢复机会。界面明确说明关闭/离开/退出后的后果。
- 这是当前操作的撤销入口，没有跨重启的回收站。JSON 备份仍是设备更换或退出应用后恢复数据的方式。

## 数据与并发边界

删除已成功写入 SQLite 后，控制器才提供恢复机会。提示存活期间只在内存中保留原记录；提示关闭即释放，不让不可见缓存长期积累。导入、清空和控制器销毁也会清理这些缓存。

每次删除都有独立的恢复身份。旧提示的关闭回调和按钮不能影响同一记录后来产生的删除机会。恢复仍受应用锁访问策略约束，所有写入由控制器串行处理。已经授权并开始的数据库写入可以完成；离开页面后的失败不会重新弹出过时提示。

恢复既有记录时不按当前设备时间重新判定“未来时间”，因此设备时钟回拨不会破坏恢复。新建、修改与导入的日期校验保持原规则。数据库恢复遇到身份冲突仍拒绝覆盖。

## 验证

- 界面覆盖持续显示、失败重试、慢写入连续点击、主动关闭、导航中晚到结果、页面切换与 320px 双倍字号。
- 控制器覆盖旧恢复身份不能恢复或释放后来删除的记录。
- 真实临时 SQLite 数据库通过触发器制造写入失败，移除故障并回拨时钟后重试，再关闭重开数据库，验证原记录全部字段一致。
- 视觉截图使用合成记录；并未以此替代真机读屏或系统身份验证验收。
