# 用户体验改进方案

## 本轮目标

让“拉了么？”在保持离线、无评判和快速记录的前提下，先解决会破坏信任感的问题，再增加一点长期观察价值。

## 本轮已实施

- 删除记录后保留原始记录身份，提供短时“撤销”恢复；删除成功后不再因为后续读取失败而误报失败。
- 选择今天或选择时间时，立即限制未来时刻，避免用户填写完才发现不能保存。
- 首页增加近七日观察摘要：有记录的天数、七天总次数和日均次数。
- 首页与知识库按全量日志中最近发生的一笔记录推荐知识卡。
- 非当前年份的历史日期显示年份，避免跨年混淆。
- 历史页系统返回回到首页；历史、首页、记录和知识页在平板上保持可读内容宽度。
- “回到今天”不可用时同步禁用点击和无障碍操作；日历图标中的文字支持系统字号。
- 增加删除恢复、跨年日期、知识推荐和撤销操作测试。

## 下一轮建议

1. 增加可选备注、颜色、不适和用力程度，默认记录流程保持一键完成。
2. 增加 30 日趋势、Bristol 分布、日期筛选和脱敏医生摘要。
3. 增加 JSON/CSV 导出、导入恢复、应用锁和数据清空确认。
4. 增加默认关闭的本地提醒，并支持关闭所有提醒。
5. 为 SQLite 增加 schema migration、真实数据库测试、时区/DST 测试和 CI。

## 验收标准

- 普通记录仍然可以选择形态后立即保存。
- 删除后可以在短时间内恢复同一条记录，时间和 ID 不改变。
- 今天或当前时间不会保存为未来发生时间。
- 320、375、414 和 768 像素宽度下无溢出，内容列不会在大屏上无限拉宽。
- 历史日期跨年后可区分，知识卡推荐与最近一笔实际记录一致。
- Flutter 环境可用后运行 `dart analyze --format machine .` 和 `flutter test`。
