# 月历与补记 UI 构思

已按 A 方案另行实现 Flutter 页面。正式版本的“回今天”文字改为“小日历＋今”图标；此 HTML 仅保留设计过程，不参与 App 运行。

这是独立的、可丢弃的交互草图，尚未接入 Flutter。双击 `calendar-ui.prototype.html` 即可体验。日期固定为 2026-09-19 14:32，所有记录均为虚构演示数据；修改只保存在页面内存，刷新即重置。

## 三个方向

| 方案 | 结构 | 判断 |
| --- | --- | --- |
| A · 轻月历 | 独立页面，上方完整自然月，下方选中日期详情 | 推荐。符合现有页面的留白与层级，也符合已讨论的独立月历入口。 |
| B · 日期票据 | 选中日期的大号票据先于月历，突出当天记录与补记 | 日期更醒目，但压缩了首屏空间。 |
| C · 历史双视图 | 历史页中切换列表/月历，保留底部导航 | 两种历史视图集中，但导航层次比 A 多。 |

底部深色栏仅为方案切换工具，不会加入 App。左右按钮或键盘左右方向键切换方案；输入框和月份弹窗内不会拦截方向键。URL 的 `?variant=A/B/C` 保留选择。顶部入口和状态栏也仅用于评审。

## 推荐 A 的页面与行为

- 首页：沿用近七日纸卷，整列作为点击范围。点哪一天便进入哪一天所在的自然月。近七日标题旁加可访问的日历入口。
- 历史：保留列表，右上角增加月历图标和“＋补记”；历史页直接补记默认昨天，时间默认当前时刻并由用户核对。
- 月历：独立页面，无底部“记录”按钮；返回准确回到来源页面。周一开始，固定六行日期位置，非本月留白。年月标题打开年份/月选择，左右箭头翻月，回今天定位今天。
- 日期状态：一条记录显示小方点，多条记录显示次数；今天加短横线，选中日期加苔绿细框和浅底色，二者可同时出现。未来日期不可点击；空白仅表示未记录。
- 当天详情：月历下直接显示时间、形态和修改入口；空状态显示“这一天还没有记录”和“补记这一天”。不在日期点击后再弹详情窗口。
- 补记：打开独立页面，带入选中日期；提供今天、昨天、其他日期、具体时间及七种形态。日期和形态选择不自动写入；点击“补记到某月某日”保存。补记单独增加确认，不改变日常记录点选即存的体验。
- 保存与修改：返回来源页面，选中保存后的日期并更新形态列表与计数；正式实现时还应更新首页、历史和 SQLite，跨日修改应同时更新原日期与新日期。
- 翻月：保留日号，目标月不存在该日则落到该月最后一天；当前月最多落到今天。可跳转闰年二月，未来月份不可选。

## 正式实现时的细节

草图不替代生产实现。Flutter 接入需要补充持久化迁移、记录时间参数、保存失败保留输入、防重复提交、返回时恢复滚动位置、设备时间变化及读屏语义。

固定六行月历可减少翻月时详情区上下跳动。在 320px 宽度下，月历减少左右内边距以保证日期的点击范围，其他区域保留原有留白。

小贴士暂不在此次范围内。原型保留在此独立目录，未混入正式 App 页面。

## 记录回顾呈现草图

双击 [insights-ui.prototype.html](insights-ui.prototype.html) 可看“记录回顾”的三种呈现方式。页面使用虚构记录，不接入 Flutter，也不写入用户数据。顶部可切换常见记录、偏硬较多、记录较少三种状态；底部深色栏或键盘左右方向键切换 A/B/C 方案。链接中的 `?variant=A/B/C&scenario=mixed/hard/sparse` 可直接定位方案与状态。底部方案切换栏只属于草图，不会加入 App。

| 方案 | 结构 | 观察 |
| --- | --- | --- |
| A · 轻入口、独立回顾 | 历史页仅多一行入口，回顾在独立页面展示 | 推荐继续深化；历史列表和首页都保持安静，解释可以完整展开。 |
| B · 历史内折叠 | 在日期列表前直接展开小结、微型分布和建议 | 更快看到内容，但展开后把最近记录推到首屏外。 |
| C · 历史双标签 | 在历史页切换“记录 / 回顾” | 可容纳长期演进，但让以日期找记录多一步切换。 |

草图用真实形态编号归类，列表中的 01/04 只是显示序号。记录不足时不下趋势判断；空白日期只表示未记录。正式实现需重写为 Flutter 组件，并接入真实数据、来源链接和无障碍语义。
